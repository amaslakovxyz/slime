# Liquid Engine v0 — JIT Gas ladder (ontology → paths → implementation)

## Context

PR #2 (`amaslakovxyz/slime`, branch `chore/gas-v0-plan`) currently holds an AOT plan in which Gas is a dev-only, never-serving build artifact. Anton has redefined the model: **Gas is a runtime just-in-time tier** — on a handler-cache miss the backend generates a handler, runs it through the unchanged harness, serves and caches it with a TTL; reuse promotes it Gas → Liquid (persistent, fixtures recorded) → Crystal (human-pinned `lee.lock`). This plan (1) defines the ontology first, (2) defines the request path and build path in those terms, (3) rewrites the spec/diagram/repo plan doc to match, and (4) implements the full ladder top-down, all pushed onto PR #2. Decisions fixed by Anton: JIT in dev **and** prod (prod will get isolated sandboxes later); Gas in process memory, Liquid/Crystal as files; Gas TTL 10 min (sliding), promotion after 3 reuses; scope = full ladder (`lee freeze`/`accept`/`test` stay deferred).

## Part A — Ontology (the vocabulary every module uses)

All terms below become types in `src/types.ts` (Step 2). Nothing outside this list is introduced.

### A1. Domain primitives

| Term | Definition |
|---|---|
| **Intent** | A named business operation (`book_ticket`). Source of truth: human-written `intents/<name>.md`. |
| **IntentSpec** | Parsed intent: `roles`, `reads`, `writes` (table+ops), `rule` (prompt text), `invariants` (named SQL), `try` (verification inputs). |
| **specHash** | sha256 hex of the raw intent markdown. Any edit changes it. |
| **Handler** | JS source `export function handler(input, db, ctx) -> { response, error? }`. Pure; no host I/O. |
| **handlerHash** | sha256 hex of the exact handler bytes. Identity of a handler on disk. |
| **Ctx** | `{ tenantId, userId, role, now }`, built by the Dispatcher from the session, never from the payload. |
| **Effect** | A proposed write `{ op, table, data?, where? }`. Handlers only propose; the kernel decides. |
| **Fixture** | Record of one harness-passing real run: `{ intent, handlerHash, input, ctx, response, effects }`. |

### A2. Layers (the harness)

A **layer** is one ordered check in the harness. Each produces either pass or a machine-readable `Reason` tagged with its `Stage`. Layers never commit; the harness owns the single transaction.

| # | Layer | Stage | Input → output | Rejects with |
|---|---|---|---|---|
| 1 | **Role check** (Gatekeeper, pre-tx) | `role` | spec, ctx → pass/fail | `ROLE_NOT_DECLARED` |
| 2 | **Sandbox + DB API** | `sandbox` | handler source, input, ctx → `HandlerResult` + collected effects. Only `db.read` (allowlisted table/columns, kernel-added `tenant_id`, equality `where`) and `db.emit` (collect only) exist inside. | `READ_TABLE_NOT_DECLARED`, `READ_COLUMN_UNKNOWN`, `HANDLER_ERROR`, `SANDBOX_TIMEOUT`, `SANDBOX_MEMORY`, `SANDBOX_CRASH` |
| 3 | **Gatekeeper** (effects) | `gatekeeper` | spec, effects → pass/fail. Declared table+op; known columns; kernel-owned columns (`tenant_id`, `id`) rejected, never filtered; update/delete address full PK by equality; effect count < 10. Any failure rejects the whole set. | `WRITE_NOT_DECLARED`, `COLUMN_UNKNOWN`, `FORBIDDEN_COLUMN`, `PK_NOT_FULLY_ADDRESSED`, `EFFECT_CAP_EXCEEDED` |
| 4 | **Invariant runner** | `invariants` | db (open tx), effects → applies effects with forced `tenant_id`, runs every invariant `SELECT`; any returned row fails. | `INVARIANT_VIOLATION` |

**Harness** = `role → BEGIN IMMEDIATE → sandbox → gatekeeper → invariants → (commit ? COMMIT : ROLLBACK)`. Same function on every path; callers choose the DB and `commit`. Type: `HarnessFn`.

### A3. Aggregate — `IntentSlot` (tier state)

**Why it exists:** a request must answer one question — *which code runs for this intent?* Tier, hit count, TTL and fixtures are facts about the same thing and must change together; otherwise e.g. a promoted handler could still be TTL-evicted. So they live in one record per intent that changes **only** through the named transitions below (DDD aggregate).

Fields: `intent, tier ("gas"|"liquid"|"crystal"), specHash, handlerHash, source, hits, expiresAt (epoch ms | null), fixtures`.

```
(none) ──miss: generate → verify on try inputs → live harness PASS──▶ GAS {hits:0, expiresAt: now+TTL, fixtures:[run0]}
GAS    ──resolve hit──▶ GAS {hits+1, expiresAt: now+TTL}                  (sliding TTL)
GAS    ──harness-passing run──▶ GAS {fixtures + run}
GAS    ──expired at lookup──▶ (none)                                      (evict; next request regenerates)
GAS    ──hits ≥ 3 AND fixtures ≥ 3──▶ LIQUID {hits:0, expiresAt:null}     (files written: handler, fixtures, state)
LIQUID ──human `lee freeze` (deferred; lee.lock written by hand in v0)──▶ CRYSTAL
any    ──specHash differs from current spec──▶ ignored at lookup (Gas evicted; Liquid/Crystal files left on disk, stale)
```

Promotion requires `fixtures.length ≥ 3` in addition to `hits ≥ 3` so a handler that keeps failing on live traffic is never persisted (reuse counts per Anton's model; only passing runs earn persistence).

Storage: **Gas** = in-process `Map` (restart = eviction). **Liquid** = `handlers/<handlerHash>.js` + `fixtures/<intent>/<handlerHash>.jsonl` + `state/<intent>.json`. **Crystal** = `lee.lock` (`{ "<intent>": LockEntry }`) + `handlers/<handlerHash>.js`. Lookup order: Crystal → Liquid → Gas. On reading Liquid/Crystal bytes, `sha256(source)` must equal the recorded hash, else throw (pinned bytes must be exact).

### A4. Paths

**Request path** (dev + prod), `dispatchIntent()`:
1. Dispatcher receives `POST /dispatch {intent, payload}`, builds ctx from the dev session.
2. Load intent (unknown → 404). `store.resolve(intent, specHash)`: Crystal → Liquid → Gas (Gas hit bumps hits + slides TTL).
3. **Hit** → harness on the real DB with `commit: true`. If tier Gas → `store.afterGasRun` (records fixture if passed; may promote). Return result.
4. **Miss** → build path's `generateWithRepair` (≤3 rounds, judged on the spec's `try` inputs against seed copies, reason codes fed back). Exhausted → 502, nothing cached. Success → harness on real DB with `commit: true` for the live payload → pass: COMMIT, `admitGas`, 200; fail: rollback, 4xx, nothing cached.
   - Repair is judged on `try` inputs, never on the live payload: a live rejection (sold out, `BAD_QTY`) is business logic, not a code defect, and must not trigger regeneration.
   - The payload is never put into the prompt (no prompt injection from requests).
   - No transaction is held during the LLM call: generation finishes before the harness opens `BEGIN IMMEDIATE`.

**Build path** (manual, dev), `lee build <intent> [--handler-file p]`: generate (or read file) → `dryRun` each `try` input on a fresh seed copy with `commit: false` → print per-try response + effects diff → `BUILD PASS`/`BUILD FAIL`. Writes nothing, touches no cache. The request path reuses its `generateWithRepair`/`dryRun` on a miss.

## Plan review ledger (SPEC gate)

**Survived (by design, carried to PR Risks):**
- Fresh JIT code commits real effects after verification on only the spec's `try` inputs plus the live harness. The harness guarantees *safety* (allowlist, tenancy, gatekeeper, invariants), not *business correctness* (e.g., a wrong discount formula commits wrong totals until the spec changes).

**Answered:**
- *"Harness fails → repair loop" should use the live payload* → live rejections are business outcomes (sold out, bad qty); feeding them back would regenerate correct code and burn rounds. Repair is judged on `try` inputs; a live failure returns 4xx and caches nothing.
- *Reuse-counted promotion could persist a handler that keeps failing* → promotion also requires ≥ 3 harness-passing runs (`fixtures.length`).
- *Pre-commit hooks could rewrite committed handler bytes and silently break hash pins* → `exclude: ^handlers/` and hash check on every Liquid/Crystal read.
- *Request payload could inject into the agent prompt* → prompts contain only spec, schema and DB API contract.
- *A long LLM call holding `BEGIN IMMEDIATE` would block all writers* → generation finishes before the harness opens the transaction; the harness itself is fully synchronous, so concurrent requests can't interleave inside it.

**Deferred:**
- Single-flight for concurrent misses (duplicate generation cost).
- Isolated per-tenant sandboxes for prod (QuickJS runs on the main event loop; ≤ 500 ms per request).
- `lee freeze`/`accept`/`test`, auth-backed sessions, JIT cost/rate limits.
